# Harness Local для Android

Самостоятельная предварительная сборка для ARM64 Xiaomi/HyperOS и других Android-устройств. Root и отдельный Termux не требуются. Небольшой APK автоматически скачивает и проверяет архив ядра (~393 МиБ) при первом запуске. В ядре находятся Ubuntu, Node.js 24.9.0, DeepSeek Harness 0.2.0-rc.2, PRoot, Git, Python 3, ripgrep, curl, компилятор C/C++ и pnpm.

## Установка

1. Установите `Harness-Local-Mobile.apk` и откройте Harness Local.
2. Дождитесь загрузки и распаковки ядра и открытия интерфейса. Рекомендуется не менее 2 ГБ свободного места. При обрыве сети загрузка продолжается с сохранённого места. SHA-256 проверяется до распаковки. Первый запуск распаковывает десятки тысяч файлов и может занять несколько минут.
3. Введите собственный API-ключ в интерфейсе Harness. Ключей в APK нет. Для облачных моделей нужен интернет; локальная установка ядра не означает наличие встроенной языковой модели.
4. Если HyperOS останавливает приложение при выключенном экране, разрешите фоновую работу в настройках батареи. Сервис использует постоянное уведомление и удерживает процессор активным до остановки ядра.

Начиная с 0.4.3 архив ядра размещён в [GitHub Releases](https://github.com/Denix22867/harness-local-android/releases/tag/v0.4.3). Приложение автоматически скачивает его по адресу из `app/src/main/assets/runtime-download.json` и проверяет размер и SHA-256. В предыдущих версиях использовалась временная ссылка Filebin со сроком хранения до 18 октября 2026 года; версия 0.4.3 от неё больше не зависит. После установки ядро хранится на телефоне; скачивание требуется только при новой установке или после очистки данных.

## Файлы и данные

Меню ⋮ → «Импортировать файлы» / «Экспортировать файл» импортирует документы в `/workspace/inbox` и экспортирует выбранные файлы из `/workspace` через системный диалог Android. Рабочая папка по умолчанию находится в `/workspace/deepseek-harness/default-workspace`. Для работы с импортированными файлами выберите `/workspace/inbox` или `/workspace` как рабочую папку в Harness.

Домашняя папка, сессии и проекты находятся в закрытом хранилище Android-приложения. Они сохраняются при остановке ядра и перезапуске приложения. Удаление приложения или очистка его данных удаляет эти файлы; экспортируйте нужные результаты заранее.

Меню ⋮ позволяет запустить/остановить локальный процесс и открыть интерфейс. В журнале отображаются ошибки запуска; секретный токен Web UI скрывается. Системное уведомление также позволяет остановить ядро.

## Проверено и ограничения

В этой среде через ARM64 QEMU и сборку PRoot из того же исходного тега проверены Node.js, чтение/запись файлов, native flock, Bash, Git, Python, ripgrep, pnpm, native Koffi и PTY. В Chromium с размером экрана 412×892 проверены авторизация Web UI, создание рабочей папки и появление настройки API-ключа: ошибок JavaScript и загрузки ресурсов нет, горизонтального переполнения нет.

Проверка выполнена в Linux-среде. Установка APK и запуск Android-варианта PRoot на физическом Xiaomi/HyperOS 3 или Android-эмуляторе не проверены. Реальные ответы моделей не проверены: API-ключ не предоставлялся. Эта сборка не подтверждает перенос всех десктопных функций.

- Electron заменён Android WebView. Десктопные окна, системный трей, захват экрана и управление другими приложениями не перенесены.
- Desktop browser/computer-use плагины, Docker, PowerShell и произвольные MCP/LSP серверы не проверены и не включены как отдельные среды. Нужные им зависимости требуется устанавливать отдельно внутри ядра.
- Linux-песочницы bwrap/Landlock зависят от ядра и ограничений устройства; их работа на Android не гарантирована. PRoot предоставляет совместимость Linux, а ограничения доступа задаёт Android. Настройки разрешений Harness сохранены; сборка не отключает их автоматически. Ошибки запуска команд в ограниченном режиме могут потребовать осознанного изменения режима разрешений в Harness.
- PRoot добавляет накладные расходы. Фоновые задачи и расписания могут останавливаться вместе с приложением по решению HyperOS.
- Android WebView должен быть актуальным. ARM32/x86 устройства не поддерживаются этой сборкой.
- Используется target SDK 28, чтобы ядро и устанавливаемые инструменты могли исполняться из закрытого хранилища приложения. Android может показать уведомление о старой целевой версии. APK предназначен для прямой установки; публикация в Google Play не подготовлена.
- Подпись — локальный ключ предварительной сборки; это не официальный релиз DeepSeek. Ключ сборки не входит в архив исходников.

## Сборка оболочки

Нужны Java 21, Android SDK platform 35 и build-tools 35.0.0, Python 3 и ECJ 3.42.0. `scripts/build_apk.py` использует AAPT2, ECJ, D8, zipalign и apksigner без Gradle. Переменная `DSH_ANDROID_SDK` выбирает SDK; по умолчанию это `tools/sdk`. ECJ ожидается в `tools/ecj.jar`.

Для восстановления файлов оболочки и нативных библиотек из предоставленного APK используйте `python scripts/recover_runtime.py <путь-к-apk>`, затем `python scripts/build_apk.py`. Ядро в компактный APK не включено; сборку оболочки можно повторить без него. Для изменения runtime его файлы можно распаковать, изменить и снова упаковать `scripts/pack_runtime.py`. Версию `RuntimeInstaller.VERSION` следует увеличить при изменении runtime.

Исходный Android-код: `app/src/main/java/org/dsh/mobile/`. Манифест: `app/src/main/AndroidManifest.xml`. Мобильный профиль: `config/android.patch.yml`. Тесты: `scripts/runtime_smoke.cjs` и `scripts/browser_smoke.cjs`. Лицензии и источники сторонних компонентов: `THIRD_PARTY.md` и `third-party-sources/`.

Регрессионный тест tests/dirent_regression.py воспроизводит прежний пропуск write-файлов, проверяет создание через временный файл + link + удаление временного файла, переименование, поиск по имени и поиск содержимого в каталоге. После исправления все шесть обычных/эмулированных файлов найдены обоими поисками; реальные симлинки пропускаются. Проверено на хосте и с Ubuntu ARM64 через QEMU под исправленным PRoot. ## Обновление 0.4.2: SSH через bash

Установите APK поверх предыдущего. OpenSSH-клиенты ssh, scp, sftp, ssh-keygen, ssh-keyscan, ssh-agent, ssh-add и sshpass вместе с недостающими библиотеками добавляются из небольшого архива внутри APK при запуске. Сервер SSH на телефоне не запускается; ключи и пароли в APK отсутствуют.

Отдельный модуль возможностей сообщает всем агентам, что для SSH используется установленный клиент через bash, а текущая рабочая папка не ограничивает адрес назначения. Для подключения нужны адрес, порт, пользователь и ключ/пароль. Подлинность сервера проверяется обычными механизмами OpenSSH; чувствительные данные не следует выводить в журнал. Разрешения Harness сохраняются. Ошибки sandbox или отказ в сетевом доступе требуют настройки соответствующих разрешений пользователем и не означают отсутствия SSH-клиента.

Проверено с ARM64-ядром: SSH по ключу и по паролю к локальному тестовому серверу с проверкой известного ключа сервера; сервер выполнил printf ssh-test-ok. Вызов того же SSH через инструмент bash в Harness вернул ssh-test-ok в OpenAI-совместимый тестовый API. Новая секция возможностей присутствует в системном сообщении модели. Для этой изолированной тестовой сессии через штатный интерфейс выбран Full access: sandbox backend под хостовым QEMU недоступен; настройки приложения по умолчанию и пользовательские разрешения не изменены. Физический Android и реальные пользовательские серверы не проверялись.

## Обновление 0.4.4: запуск HTML и экспорт из /root

HTML-файлы открываются одним нажатием в дереве файлов Harness, ссылках на файлы в чате и через новый пункт ⋮ → «Файлы». Предпросмотр работает в отдельном WebView: выполняется JavaScript, загружаются относительные CSS/JS-ресурсы и данные через fetch. Кнопки в панели позволяют обновить страницу и вернуться в Harness. Предпросмотр обслуживает папку HTML-файла и её подпапки; серверная часть проекта автоматически не запускается.

«Файлы» и «Экспортировать файл» теперь предлагают обе папки: `/workspace` и `/root`. `/root` соответствует постоянной домашней папке приложения, поэтому созданные там проекты доступны для просмотра и экспорта. Название и MIME-тип экспортируемого файла сохраняются в системном диалоге Android. Эмулированные hardlink PRoot учитываются при открытии и экспорте: файл, созданный инструментом write, читается из постоянного backing-каталога.

HTML обслуживается локальным сервером на отдельном loopback-адресе и порте, с непредсказуемым адресом сеанса. WebView предпросмотра не имеет JavaScript-моста и доступа к file/content URL. Выход за пределы папки HTML и ссылки на посторонние файлы отклоняются; настоящие ссылки PRoot на backing-файлы обрабатываются отдельно.

Проверено на хосте: пути `/root` и `/workspace`, чтение PRoot write-файлов, имена с пробелами и Unicode, отклонение выхода из папки и посторонних симлинков. В Chromium на ширине 360 пикселей проверены отображение HTML, JavaScript по нажатию, CSS, JS, fetch, HTML через PRoot-ссылку, обработка HTML-нажатий в дереве и чате и прежнее поведение остальных файлов.

На Android 9 x86-эмуляторе отдельной сборкой оболочки без ARM64-библиотек проверены выбор проекта из `/root`, открытие HTML с CSS, выполнение JavaScript по нажатию и возврат в Harness. Экспорт из `/root` через системный диалог Android сохранил HTML в «Загрузки»; байты сохранённого файла совпали с исходником. Полный ARM64-APK на физическом телефоне в этой среде не проверялся.

APK обновляется прежним ключом и package ID, versionCode увеличен до 10. Версия установленного ядра и адрес его загрузки из релиза 0.4.3 сохранены: обновление не требует скачивать ядро заново и сохраняет проекты и настройки.

## Обновление 0.4.5: настройка лимита ответа

В мобильную форму OpenAI-compatible API добавлено поле «Лимит ответа (токены)». Раньше форма всегда сохраняла 8192 и не позволяла изменить значение; это могло приводить к обрезанию длинных ответов, особенно когда рассуждения входили в тот же бюджет. Теперь можно указать, например, 32768, если сервер и модель поддерживают такой лимит.

Существующие значения сохраняются до изменения пользователем. При сохранении сохраняется и настроенное contextWindow. Bootstrap уже передаёт maxTokens в конфигурацию Harness; выбранное значение применяется после перезапуска ядра. Увеличение лимита не гарантирует отсутствие обрезания на стороне провайдера и может увеличить фактический расход токенов.

Package ID, подпись и версия большого ядра сохранены, versionCode увеличен до 11. Обновление устанавливается поверх текущего APK без повторной загрузки ядра и без удаления проектов или настроек.

Проверены сборка и подпись APK, а также применение лимитов 8192, 32768 и 65536 в профиле Harness через bootstrap на изолированных тестовых настройках. Платные API в проверках не вызывались; реальный ответ DeepSeek с пользовательским ключом в этой среде не проверялся.

## Обновление 0.4.6: браузерные инструменты для агента

Cordis-плагин добавляет инструмент `browser` с действиями open, snapshot, screenshot, click, type, key, evaluate, wait и close. Реальный Android WebView выполняет страницу и canvas, нативные события обеспечивают нажатия и клавиши. Можно открыть HTML из /root или /workspace либо HTTP(S)-страницу, получить DOM и ошибки консоли, проверить мобильный или широкий viewport. Браузер видимый; приложение нужно держать на переднем плане.

В форме провайдера добавлен флажок «Модель принимает изображения». Для поддерживающей изображения модели PNG проходит штатные upstream MCP image admission и durable image projection. Для текстовой модели возвращаются DOM, консоль, сообщение об ограничении и путь к PNG; визуальная проверка не заявляется. Скриншоты сохраняются в /root/.harness-browser/screenshots/. Отдельная установка Chromium не требуется.

Мост слушает только loopback, использует случайный bearer-токен в приватном файле 0600 и ограничивает браузер одной сессией. WebView не имеет JavaScript-моста и доступа к file/content URL; интерфейс управления Harness нельзя открыть через этот инструмент. Служебные скрытые файлы не обслуживаются сервером HTML-предпросмотра.

На Android 9 x86-эмуляторе отдельной тестовой сборкой без ARM64-ядра проверены три режима тестового canvas, реальные нажатия, пиксели PNG, ввод, клавиши, консоль, владение сессией, закрытие и широкий viewport за пределами физической ширины телефона. Через реальный upstream MCP helper проверены допуск и durable image reference снимка с тестовыми LLM/attachment service, а также ограничение для текстовой модели. Игра пользователя и платные API не вызывались; полный ARM64-APK на физическом телефоне не проверялся.

Подпись, package ID и версия установленного ядра сохранены, versionCode увеличен до 12. APK устанавливается поверх текущего без повторной загрузки ядра, с сохранением проектов и настроек.
